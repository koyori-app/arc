# 稲妻線の出し入れと行ごとの決まりの設計書

| 項目 | 値 |
|------|-----|
| 文書ID | `design/progress-line` |
| 関連 | `design/view-range`（この上に積む）、`design/bar-marks`、task の cmd_407（稲妻線の決まり）、cmd_411（ガントの作り直し） |
| 状態 | 実装 |
| 基準 | `feat/gantt-view-range` の `75d84ca` |

## 1. 要約

使う側が、稲妻線（進捗の線）を描くか、どの決まりで描くかを選べるようにする。

今の線は、今日の線の上端から始まり、各行の進みの点を上から順に斜めに結び、今日の線の下端で終わる。
このため、遅れの行が続くと線が棒の間を斜めに横切る。また、済んだ課題も棒の終わりで折れ、遅れのように左へ尖る。
task のガントは、稲妻線を既定で消し、使う人が点けられるようにする。点けた時は cmd_407 で決めた決まりで描く。

| 問い | 採る答え |
|------|---------|
| 一、出し入れ | `options_json` の `progress_line`: `"shown"`（既定。今の線）、`"hidden"`（描かない）、`"by_row"`（行ごとの決まり）（3.1） |
| 二、行ごとの決まり | 遅れか先行の行だけ今日の線から尖り、その行の下の境で今日の線へ戻る（3.2） |
| 三、形と色 | 実線 2px と折れ目の点。色の名 `ProgressLine`（落ち先は `Progress`）（3.3） |

既定の `"shown"` は今の線のまま、一字も変えない。今の線を描く使う側と、出力を縛る試験を崩さぬためである。

## 2. 今の作りで確かめたこと

- 線は `progress.rs` の `progress_line` が求める。今日が図に無ければ、各行の進みの点を結ぶだけの旧い形になる。
- 0% の行は、進みの点が今日より右へ出ぬよう抑える。済みの行を区別する決まりは無い。
- 線は赤の 6,3 の破線で、幅は `PROGRESS_LINE_STROKE_W`。
- Redmine の稲妻線は、済みの行と未着手の行を今日の線の上に通し、今日が表示の範囲の外なら線を描かない。

## 3. 口の形

### 3.1 `progress_line`

- `"shown"`（既定）: 今の線。
- `"hidden"`: 線を描かない。
- `"by_row"`: 3.2 の決まりで描く。
- それ以外の値は `parse_error` で断る。`null` は鍵が無いのと同じ。

### 3.2 `by_row` の決まり

線は今日の線の上を、最初の行の上の境から最後の行の下の境まで下る。行ごとに次の決まりで尖る。

| 行 | 線の通り道 |
|----|-----------|
| 進みのある行（進捗率が 0% を越え 100% 未満） | 行の上の境で今日の線を離れ、行の真ん中の高さで進みの位置へ尖り、行の下の境で今日の線へ戻る。進みが今日より前なら左へ（遅れ）、後なら右へ（先行） |
| 0% で予定開始を過ぎた行 | 同じ形で、予定開始の位置へ尖る |
| 済みの行（行の `state` が `done`） | 今日の線のまま。進捗率は問わない |
| 進捗率 100% で `state` が `done` でない行 | 進みのある行と同じ形で、棒の終わり（目安の期限）へ尖る。閉じ忘れが見えるようにするため |
| まだ始まらぬ 0% の行 | 今日の線のまま |
| 群れの行 | 今日の線のまま |

- 尖る先が今日の線の上にある行は、尖らない。
- 今日が図に無い時（`today` を渡さぬ時、または今日が図の日の外の時）は、線を描かない。今日の線が無ければ、遅れと先行を測る基準が無いためである。
- `view` を渡した図では、今日が範囲の日の内でだけ描く。尖る先が範囲の外なら、範囲の端に留める。

### 3.3 形と色

- 実線で、幅は 2px（`BY_ROW_LINE_STROKE_W`）。
- 尖った先（今日の線の上に無い折れ目）ごとに、径 2.5px（`BY_ROW_POINT_RADIUS_PX`）の点を描く（`RoundRectSemantic::ProgressPoint`、class `progress-point`）。
- 線と点の色は、色の名 `ProgressLine`。既定の色の表には入れず、落ち先は `Progress`（今の線の色）。canvas の色の番号は 22。
- 凡例の線の見本は今のまま変えない。task は凡例を隠して自前の凡例を描く。

## 4. 描き方

- 行ごとの尖る先は `by_row_bend`、線の点は `progress_line_by_row` が求める。どちらも `progress.rs` にあり、今の `progress_line` には触れない。
- 線の点は、上の境、尖る先、下の境の三つを行ごとに足し、続けて同じ点が並ぶ時は一つにする。
- 済みの判定は、行の一覧の `state` が `done` かだけで決める。進捗率 100% は済みとしない。行の一覧の無い図には済みの行が無い。
- task は完了の状態の課題に `state: done` を渡す（完了かどうかは task の側が状態から決める）。

## 5. 試験

- `display_list/progress_line_tests.rs`: `"shown"` が今の線と同じこと。`"hidden"` は描かない。`"by_row"` の通り道（遅れ、済み、0% で開始を過ぎた行、まだ始まらぬ行、先行）。100% でも `done` でない行が尖ること。0% で `done` の行が今日の線のままのこと。実線と点と色の落ち先。`state` が `done` の行。群れの行。今日が図に無い時。範囲の端に留めること。
- `tests/progress_line_json.rs`: `"shown"` と `null` は鍵が無いのと同じ。`"hidden"` と `"by_row"` の読み。断る値。
- 変異で確かめたこと: 済みの判定を外す変異、100% を済みとして扱う変異、0% で開始を過ぎた行の決まりを外す変異で、試験が落ちる。

- Storybook: `ProgressLineByRow`、`ProgressLineByRowCanvas`。
